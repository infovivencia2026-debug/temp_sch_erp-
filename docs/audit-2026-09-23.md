# Product audit, 23 September 2026 — what is still open

Twelve read-only auditors swept the product on one day, each on its own
axis: unreachable capability, features that do not do what they say, UI,
authorisation and tenancy, money, admissions, attendance and marks,
messaging, the parent portal, Indian statutory rules, scale, and data
integrity. Every finding below was verified in the code by a second pass.

This file is the **backlog** — what was found and has *not* yet been fixed.
Fixed the same day (see git log from `1c6770e8` onward): the simulated
"pay" button live in production; absent-as-zero and moderation on the
report card; cross-institution permission union; guardian rewriting a
co-guardian's phone; `{{school_name}}` unsupplied on every WhatsApp alert;
the exam-eligibility tile that was the length of a `LIMIT 100`; the
receipt counter wedging on a back-date; per-line flat concessions; the
whole-year invoice re-billed term by term; tenant-wise system events and
audit paging; the catalogue-key guardrail test. Later the same day
(`843c7e49`): alerts to the primary guardian only, credentials by email
only, a guardian link that can be blocked or ended, identity numbers
redacted from audit bodies, the sign-in throttle by address, and the
public privacy notice at /privacy. The two forums were removed outright
(`9b42d991`), which closes their moderation findings.

Remove an item here when it ships. Keep the file honest.

## Tier 1 — wrong on documents a school signs, or money

- **Cancelling a carried-forward invoice makes last year's debt vanish**,
  and the parent's ledger then shows the school owes *them*.
  `fee_arrears.go:53-113`, `activities.go:404`.
- **The parent's ledger credits bounced cheques and cancelled invoices** —
  no status filter on either leg; header totals disagree with the rows.
  `fees.go:170-203`.
- **Wallet balance drifts from its ledger**: the trigger SUMs before it
  locks; top-up and adjustment take no lock. `00322_wallet.sql:63-88`,
  `wallet.go:234,309`. One line: `PERFORM 1 FROM wallet_accounts WHERE id
  = target FOR UPDATE` before the SUM.
- **TDS slabs are FY 2024-25**, hardcoded in Go against the file's own
  "held as data" comment; Form 16 absent; **ESI drops staff mid
  contribution period**, the exact rule the migration warns about.
  `payroll_tax.go:34-59`, `payroll_statutory.go:267`. Telangana PT slabs
  are seeded for every school.
- Bulk marks import **rewrites a paper's `max_marks` under marks already
  entered** and lets the CSV supply `grade`. `bulk_import.go:1735,1861`.
- Bulk attendance import **overwrites without `corrected_from`** and skips
  the month close. `bulk_import.go:2656`.
- A teacher's correction that leaves `status` unchanged (minutes late, a
  remark) is **silently discarded**. `attendance.go:159-168`.
- Admission-approval screen shows concessions with integer division
  (`amount_paise / 100`). `admission_approval.go:144`.

## Tier 3 — built but unreachable, or not what the Summary says

Endpoints with no caller (a person is blocked): **librarian cannot issue a
book** (`/ops/library/issue`); parent-forum and student-wall **moderation**
(reports go into a black hole); recruitment **interviews and offers**;
parent **PTM booking**; grievance **escalation** and parent
**satisfaction**; MDM norms/foodgrain; absence follow-up call logging;
WhatsApp **template submission**; appraisal moderation; and a dozen single
routes (remove group member, delete claim line, delete house, …).

Screens wired to keys the catalogue no longer has — frozen in
`web/src/features/catalog-keys.test.ts`, twenty of them: purchase
requisition→PO→GRN→3-way match (16 endpoints), 360 evaluation (and half
its API never called), custom report builder, department reports,
performance analytics, appraisals, instruction hours, …

Summaries that promise what screens disclaim: Tally "automated sync",
Zoom/Meet/Teams, scheduled backups, printable application answers
(`GET /applications/{id}/answers` has no caller), waivable library fines
(₹1/day hardcoded in the browser).

Numbers from degenerate sources: RTE compliance from 0/0 shows green;
section average counts unmarked cards as zero; "Live leads" counts dead
ones; annual salary extrapolated from one payslip; pass rate per mark-row.

Writes accepted and discarded (200 OK): rescheduling a live class, moving
a bus between campuses, re-targeting a worksheet, several reasons/notes.

The in-app assistant directs staff to **177 screens that do not exist** —
help is generated from a superseded CSV (`scripts/gen_answers.py:39`).

**Admission drip campaigns never run** (no cron entry). The counsellors'
"lost" path writes free text and leaves the analysis columns NULL. The
RTE pipeline is broken at every join (`quota` never written at the
counter; seat guard ignores the 25%; lottery import has no UI;
`admission_sessions` has no CRUD). Statutory fields collected on the
application are dropped at conversion.

Messaging: three highest-volume sends carry **no dedupe key**
(`fee_reminders.go:203`, `attendance.go:414`, `report_card_approval.go:632`);
absence alerts duplicate once per period; circular fan-out dedupes for
half the school; a provider send can be replayed on a late error;
`occurrenceFor` keys on how many channels happened to be usable; opt-out
is per enquiry row and governs one feature; no STOP handling; quiet hours
never apply to direct sends; templates carrying a password are submitted
as UTILITY; nothing counts SMS segments.

## Tier 4 — the `LIMIT` shape (silently wrong, not slow)

`collect()` + a hard `LIMIT` is the house style for ~200 list endpoints;
real paging exists in five. Tiles and mass actions fed from capped arrays:
**Defaulters** ("Remind all N shown" sends only the 500 largest debts;
`last_fee_reminder_at` stamped before the send), **Payments** ("Settled
₹X" is the last 300 receipts), **Finance overview** (tile ₹18L, table
₹6L), **Library fines** (NULLs-last sort drops the books still out),
concessions, petty cash, POs, staff exits, alumni, behaviour notes (a
search for last term's incident reads as "no record"), leave, department
students (sort is client-side over 600), applications, all-messages (a
class with older mail is not offered as a filter), fuel spend, bus stop
alerts (morning run truncated).

Mitigations already in the repo: declare the cap as
`bento/FinanceDashboard.tsx:385` does; order actionable rows first as
`hostel_life.go:103` does; page-walk as `ba226d1e` does.

`/portal/live` runs **seven unindexed full-table `max()` scans every 30s
per open tab** and calls a blanket `invalidateQueries()` — also why the
service never scales to zero. `live.go:61-98`, `live.ts:118`. Six indexes
and the narrowed invalidate in `lib/invalidate.ts`.

Whole-school fee run is ~8,400 round trips in one request (`fees.go:1031`);
bulk logins and marks import likewise. Batch as `bulk_import.go:4605`
teaches, or queue.

`audit_log`, `message_log`, `notifications`, `transport_*_events`: no
retention (kept deliberately — see `app_events` — but the dashboards that
scan them unbounded need date bounds: `messaging.go:2929`,
`platform_usage.go:118`, `admin_inbox.go:511`).

## Tier 5 — deploy risk

Every `CREATE INDEX` in the tree is non-`CONCURRENTLY` and every `ADD
CONSTRAINT CHECK` lacks `NOT VALID`; the migrate job runs while the old
revision serves. `00325` re-validates all of `payments` under `ACCESS
EXCLUSIVE`. Pattern to adopt: `-- +goose NO TRANSACTION` + `CONCURRENTLY`
(see `00340`), and `NOT VALID` + `VALIDATE CONSTRAINT`.

The core academic parents (`students`, `sections`, `classes`,
`academic_years`) never got the `(id, institution_id)` composite key that
00097 gave the finance subtree; 104 child FKs reference `students(id)`
alone. `00310`/`00311` have primary keys whose namespace is shared across
tenants.

A vacated roll number can never be reused (`enrollments_roll_no_unique`
covers closed rows).
