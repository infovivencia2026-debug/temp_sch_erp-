## Data scopes

| Scope | Boundary | Enforced by |
|---|---|---|
| **Platform** | Every institution. Requires `app.is_platform_admin`. | Postgres RLS |
| **Institution** | The caller's tenant. Enforced by Postgres RLS. | Postgres RLS |
| **Campus** | Campuses named on the user's role assignments. | `internal/scope` + explicit SQL predicate |
| **Department** | Departments where `departments.head_user_id` is the caller. | `internal/scope` + explicit SQL predicate |
| **Assigned classes** | Sections the caller teaches or is class teacher of. | `internal/scope` + explicit SQL predicate |
| **Self** | The caller's own student record. | `internal/scope` + explicit SQL predicate |
| **Linked children** | Students the caller is a guardian of. | `internal/scope` + explicit SQL predicate |

RLS covers only the tenant boundary. The four narrower scopes are enforced in the application, because every row involved belongs to the same institution and the `tenant_isolation` policy admits all of them. A handler that forgets its scope filter leaks data *within* a tenant — which is why `internal/scope` returns `FALSE` for an empty set rather than omitting the clause.
