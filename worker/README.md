# The ERP backend on Cloudflare Workers + D1

This replaces the Go service on Cloud Run and Neon Postgres. The web
frontend on Pages and the files on R2 stay where they are; the Pages proxy
(`web/functions/[[path]].ts`) is pointed at this Worker instead of Cloud Run
at cutover by changing `API_ORIGIN` in `web/wrangler.toml`.

Read [docs/d1-migration.md](../docs/d1-migration.md) for why the data moved
and what Postgres features had to be re-implemented here.

## Layout

| Path | What |
|---|---|
| `src/index.ts` | Entry: health, login, logout, session, then the route table |
| `src/router.ts` | Chi-style patterns, a permission per route |
| `src/identity.ts` | Who is calling: session -> user, roles, permissions, school |
| `src/tenant.ts` | The school's own D1 database from its row in CONTROL |
| `src/auth/` | bcrypt-with-pepper verify (same bytes as the Go hasher), session cookie |
| `src/routes/` | One file per Go handler group; `index.ts` registers them |
| `db/control.sql` | The platform database: schools, plans, subscriptions, platform staff, sign-in index, sessions |
| `db/tenant.sql` | The per-school schema, generated by `scripts/d1/pg_to_d1.py` |
| `scripts/provision-school.sh` | Creates a school's database, applies the schema, adds the binding, registers it |
| `PORTING.md` | The contract every ported route follows |

## Tenancy

One D1 database per school, plus one CONTROL database. Isolation is the
database boundary, not a WHERE clause. Each school's database is a Worker
binding named `TENANT_<SLUG>`, recorded on the school's row in CONTROL, so a
request resolves its school once and every query after that can only see
that school. Sessions and the sign-in index live in CONTROL because the
cookie arrives before the school is known.

## First deploy

```
cd worker
npm install --legacy-peer-deps
npx wrangler login
npx wrangler d1 create school-erp-control          # paste the id into wrangler.jsonc
npx wrangler d1 execute CONTROL --remote --yes --file=db/control.sql
npx wrangler secret put PASSWORD_PEPPER             # the SAME value as the Go server's
scripts/provision-school.sh <slug> "<School name>" "<Short>"
npx wrangler deploy
```

Then load the school's data: run `scripts/d1/migrate.sh export` at the repo
root, and execute the resulting `data.sql` against `school-erp-<slug>`
(one school per database; the export currently produces one file for the
whole Postgres, so for the first school that is the whole thing). Copy the
school's `institutions` row, plans and subscription into CONTROL, and fill
`login_index` from the school's users:

```
INSERT INTO login_index (kind, value, institution_id, user_id, created_at)
SELECT 'email', email, institution_id, id, created_at FROM users WHERE email IS NOT NULL
UNION ALL SELECT 'phone', phone, institution_id, id, created_at FROM users WHERE phone IS NOT NULL
UNION ALL SELECT 'username', username, institution_id, id, created_at FROM users WHERE username IS NOT NULL;
```

(run that against the school database, export the rows, insert into CONTROL).

## Local development

```
cd worker
echo 'PASSWORD_PEPPER=<32+ chars>' > .dev.vars
echo 'COOKIE_SECURE=false' >> .dev.vars
npx wrangler d1 execute CONTROL --local --file=db/control.sql
scripts/provision-school.sh demo "Demo School" "Demo" --local
npx wrangler dev
```

## Cutover checklist

1. Every route the web client calls answers something other than 501 here
   (`grep -c 501` is not the test; hit them).
2. `PASSWORD_PEPPER` on the Worker equals the Cloud Run secret, or nobody
   can sign in.
3. Freeze writes on Cloud Run, run the export, load D1, verify counts.
4. Change `API_ORIGIN` in `web/wrangler.toml` to the Worker's URL, push,
   let Pages build.
5. Keep Cloud Run and Neon up for a week as the rollback.

## Not here yet

Background jobs (River) become Cloudflare Queues consumers; live updates
(LISTEN/NOTIFY) become a Durable Object per school; email, SMS, WhatsApp,
push, PDFs, Tally and payment gateways are 501 stubs listed in each route
file. The Go server keeps running until every one of these is closed.
